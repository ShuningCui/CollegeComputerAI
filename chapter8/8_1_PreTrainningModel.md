## 预训练模型

---
### **生成式模型**
+ 生成式模型到底是什么呢？其*核心是教会模型生成与训练数据相似的新数据*。
+ 例如，如果在一个猫的图像数据集上训练一个模型，就可以使用该模型生成看起来可能来自原始数据集的新猫图像。当然，除了创建新颖的图像，还可以生成视频以及生成具有特定风格的文本。

机器学习领域提供了大量在大型数据集上训练的开放的预训练模型，任何人都可以使用。从头开始训练这些模型可能成本高昂且耗时，但预训练模型提供了一种实用且高效的替代方案。这些预训练模型可以生成新数据、对现有数据进行分类，并适应新的应用场景。

---

### **获取预训练模型**

- Hugging Face镜像站（HF-Mirror）：这是一个公益项目，为国内用户提供稳定、快速的镜像服务，可无障碍访问HuggingFace的资源。可通过网页直接在HF-Mirror站点搜索所需模型，并在其主页的"Files and Version"部分下载文件。

- ModelScope社区：提供了多种下载模型的方式。如果模型已集成至ModelScope的Library中，可以通过相应代码快速下载并加载模型。也可以通过modelscope modelhub，从repos下载文件或将它们集成到库中。对于公开模型，还可以直接使用Git进行克隆，私有模型下载需要登录并使用个人访问令牌，可在ModelScope官网个人中心获取。

----

### **获取预训练模型**

- GitHub：许多开源项目会在上面发布预训练模型，如清华THU Chatbot和GPT2-Chinese等项目，用户可以根据自己的需要进行相应的修改和扩展。

- PaddlePaddle模型库：PaddlePaddle不断丰富预训练模型库，在其官方网站上有各种模型介绍，进入官方模型介绍页面，下拉到readme页面的最下方，可看到"Released models"表格，表格中的模型名称是超链接，链接对应的是该模型的预训练权重下载地址，点击即可下载。

---

### **通过ModelScope获取模型**

由于一些模型需要登陆取得许可才可以下载，所以推荐在下载之前注册一下。进入Modelscope 的网站注册：<https://modelscope.cn/>。

如何从Modelsope下载模型，网站上有详细的说明。通常在ModelScope社区下载模型有三种方式：使用命令行工具下载、使用 SDK 下载以及通过 Git下载。本文以SDK下载为例。其他的方式参看网站帮助：<https://modelscope.cn/docs/models/download>

---

### **通过ModelScope获取模型**

无论是使用命令行还是ModelScope SDK，模型会下载到\~/.cache/modelscope/hub默认路径下。如果需要修改 cache 目录，可以手动设置环境变量：MODELSCOPE_CACHE，完成设置后，模型将下载到该环境变量指定的目录中。也可以在下载的时候指定目录。

首先需要安装必要的包：

pip install modelscope

---

### **通过ModelScope获取模型**

接下来在Modelscope社区搜索自己需要的模型。找了之后进入模型的介绍页，点击模型名字下面的复制按钮，复制模型的ID（以通义千问2.5-0.5B-Instruct为例）：

打开vscode，输入以下代码：

```python
from modelscope.hub.snapshot_download import snapshot_download
model_id = 'Qwen/Qwen2.5-0.5B-Instruct' # 从网页复制的模型id
# 下载模型
model_dir = snapshot_download(model_id)
```
可以通过参数cache_dir或local_dir将模型保存到指定的目录。

### **社会与伦理**

+ *偏见与公平性：算法世界里的偏见困境*。生成式模型的训练过程依赖于海量数据集，而这些数据集往往不可避免地存在各种偏差。这些偏差可能源于数据采集时的样本选择不均衡，也可能受到社会固有观念的影响。
>例如，在训练用于图像生成的模型时，如果数据集中女性职业形象多局限于护士、教师等传统职业，而男性职业形象却涵盖工程师、科学家等多元领域，那么训练出的模型在生成职业相关图像时，就很容易强化性别刻板印象。在自然语言处理领域，生成式模型可能会因训练数据中的性别、种族、地域等偏见，生成带有歧视性的文本内容。

---
### **社会与伦理**

+ 更值得警惕的是，这些偏差在模型不断迭代和应用过程中，*还可能被进一步放大*。学术研究表明，一些招聘筛选的生成式模型，由于训练数据中存在的历史招聘偏见，导致对某些特定群体产生系统性歧视，直接影响到就业公平。
+ 因此，在使用生成式模型时，开发者和使用者必须重视数据的预处理和偏差检测，通过技术手段和伦理审查，最大程度地减轻模型偏差，确保技术应用的公平性。

---

### **社会与伦理**

+ *监管：构建技术发展的制度牢笼*。面对生成式模型带来的潜在风险，建立健全的监管体系已成为全球共识。在技术快速迭代的背景下，传统的监管模式往往难以跟上创新的步伐，因此需要构建一套涵盖技术、法律、伦理等多维度的监管框架。

+ *首先，透明度要求至关重要*，模型开发者应公开其数据来源、训练方法和算法原理，以便接受社会监督；其次，制定统一的伦理准则，明确规定生成式模型在不同领域应用的边界和底线；最后，完善法律框架，针对深度伪造、数据滥用等违法行为制定具体的处罚措施。

---
### **社会与伦理**

+ 欧盟在人工智能监管方面走在世界前列，其发布的《人工智能法案》，对高风险人工智能系统的开发、部署和使用提出了严格要求，为全球生成式模型监管提供了有益参考。
+ 在人工智能技术不断革新的今天，生成式模型的应用前景广阔，但我们必须以审慎和负责任的态度对待它。

---

### **现状与未来**

+ 生成模型的研究与开发可追溯至几十年前，早期*主要聚焦于基于规则的系统*。随着*计算能力*的指数级提升与*海量数据*的积累，生成模型逐步转向统计方法与机器学习领域。
+ 深度学习作为机器学习的前沿范式，在图像和语音识别领域取得重大突破，为生成模型的发展注入强大动力。尽管卷积神经网络（CNNs）和循环神经网络（RNNs）早在几十年前就已诞生，但真正迎来爆发式增长并广泛应用则是近十年的事。其中，*卷积神经网络革新了图像处理技术，循环神经网络则赋予了序列数据建模能力*，推动文本翻译和文本生成等任务迈向新台阶。

---
### **现状与未来**

+ 2014 年，伊恩·古德费洛（Ian Goodfellow）提出的*生成对抗网络*（GANs）及其衍生的深度卷积生成对抗网络（DCGANs）、条件生成对抗网络等，开启了生成模型发展的新纪元。
+ 在自然语言处理（NLP）领域，曾经主导语言建模的循环神经网络（RNNs）也逐渐被Transformer架构取代，以GPT为代表的模型在语言理解、文本生成、机器翻译等任务中不断刷新性能上限，特别是GPT凭借强大的上下文关联与文本生成能力风靡全球，进而引发了生成式语言模型的研发热潮。

---

### **现状与未来**

+ 清华大学、北京大学、中国科学院等单位在扩散模型优化、多模态融合等方向取得多项创新性成果。
+ 百度推出的文心一言，不仅具备优秀的文本生成能力，还通过与百度搜索、智能设备的深度整合，构建起"技术-应用-服务"的完整生态；
+ 字节跳动的豆包，基于海量数据训练与先进算法优化，在多语言交互、复杂任务处理上表现突出；
+ 商汤科技依托其深厚的计算机视觉技术积累，在图像生成、视频合成领域持续发力，相关技术广泛应用于智慧城市、影视制作等多个场景。

---

### **现状与未来**

+ 近年来，得益于全球范围内研究资源的快速积累与开发生态的完善，生成式人工智能领域的准入门槛显著降低。
+ 一方面，开源社区的蓬勃发展为技术创新提供了沃土，GitHub等平台上丰富的开源项目、模型代码与数据集，极大地便利了开发者的学习与实践。
+ 另一方面，大型科技企业纷纷推出各类生成式模型，自2023年起，ChatGPT、DALL·E、Imagen、Stable Diffusion、Llama、Mistral等新一代多模态模型相继问世，实现了图像、文本、代码、视频等多类型内容的高质量生成。
  
---

### **现状与未来**

+ 从模型开发主体来看，当前人工智能模型的创建主要依托雄厚资金支持或开源协作。国际上，OpenAI开发ChatGPT、DALL·E和Sora，谷歌推出Imagen、Bard和Gemini，Meta打造Llama和Code Llama等，这些模型在发布形式上*差异显著*，部分通过特定用户界面开放使用，部分支持开发者通过API调用，还有些仅以研究报告形式公开，实际无法访问。*若模型代码与权重同时发布，通常被视为开源版本，但出于商业战略考量，企业往往会对关键资源进行限制*。

---

### **现状与未来**

+ 在中国，企业在开源策略上也呈现多元探索态势。
+ 华为推出盘古大模型，并将部分技术与代码开源，吸引产学研各界共同参与优化，推动模型在能源、金融等行业的落地应用；
+ 智谱AI开源的GLM系列模型，凭借高效的训练机制与良好的性能表现，在学术界和产业界引发广泛关注
+ 国内的模型开源也面临数据不完整、许可证限制等问题。由于机器学习系统的复杂性，仅有源代码或模型权重*难以实现模型的完整复现*，训练数据、关键参数等核心要素往往*未被完全公开*。同时，多数模型附带的许可证与开源促进会的标准存在差异，这也是*业界常使用"开放获取"而非"开源"表述的重要原因*。
